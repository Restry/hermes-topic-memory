# Hermes Topic Memory

- register: `product`
- product shape: private Topic Memory control center
- primary users: the owner/operator managing a private 51-topic memory estate on desktop and mobile

## Purpose

Help the operator understand the estate, inspect recall decisions, and safely maintain one canonical, versioned memory document per topic. Historical questions and version-bound QA cache are distinct sources of truth.

## Product character

Precise, technical, restrained. Dense but legible. This is an operational control surface, not a generic SaaS dashboard.

## Principles

1. Source truth stays visible: topic identity, version, state, counts, timestamps, selection reasons, and attribution are explicit.
2. Privacy is the default: authenticate every API; never expose canonical bodies, answers, credentials, or local paths in the static shell.
3. Agent choices are explained: selected topics and reasons remain inspectable; there is no hidden all-topic search or default global topic.
4. Destructive actions are reversible: archive, recycle, restore, versioned rollback, and explicit permanent-delete confirmation.
5. Density serves comprehension: search, filter, sort, compact telemetry, and honest empty/error/loading states replace decorative UI.

## Boundaries

Not a full MindMemOS clone. Do not add credential management, model routing, graph views, Dreaming, arbitrary shell access, or unsupported MM concepts. Avoid cream SaaS styling, identical rounded card grids, decorative AI/glass/gradient UI, and ornamental animation.

## Accessibility and devices

WCAG AA contrast, complete keyboard operation, visible focus, reduced-motion support, accessible table fallbacks for charts, and a usable responsive layout down to 375px. Dense tables may scroll within their own region.
